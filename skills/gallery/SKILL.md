# /gallery — One-file diagram deck (tabbed HTML + export toolbar)

> Gather every diagram of a feature (D2/PlantUML/BPMN `.svg` + Mermaid blocks in `.md`) into ONE self-contained HTML: one tab per diagram type, dark theme, **Copy/PNG/PDF** export toolbar. Hand a stakeholder a single file instead of a folder.

## Goal

Run `gallery-build.mjs` over `docs/{feature}/` (+ `docs/_shared/`) → produce `docs/{feature}/{feature}-gallery.html` (openable by double-click, no server, no runtime network for SVGs).

## Constraints

- **Fixed output** `docs/{feature}/{feature}-gallery.html` (override `--out`). Idempotent — re-run overwrites.
- **`--feature` required** (no guessing) — the gallery is per-feature. Cross-feature → run per feature, or copy artifacts into `docs/_shared/` first.
- **Render via `gallery-build.mjs`** (this skill's resource) — do NOT write the HTML by hand. The builder inlines every `.svg` and renders ```mermaid blocks via `mmdc` when available.
- **Reuse the Cocoon toolbar** — the template inherits html2canvas + jsPDF (SRI-pinned) from `skills/system-design/resources/c4-export-template.html` (MIT). Do NOT change the export JS without syncing both.
- **Tabs by source folder** — Architecture / Data flow / Data model / Process (BPMN) / Use cases / Code flow / SRS diagrams / Other. Unknown folder → "Other".
- **L1 approval** before Write (the HTML is generated by the script; show what will be included).
- **NO L3 iterate** — open the HTML to review.
- **Bilingual** — the deck title uses the feature slug; captions come from filenames/headings AS-IS.

## Inputs

```
/gallery --feature <slug>                 # build docs/{feature}/{feature}-gallery.html
/gallery --feature <slug> --out x.html    # custom output path
```

## Context (dynamic)

Today: !`date +%Y-%m-%d`
Available features: !`ls -d docs/*/ 2>/dev/null | xargs -I{} basename {} | head -20`
node: !`command -v node >/dev/null && echo "✅ $(node --version)" || echo "❌ node required"`
mmdc (for mermaid blocks): !`command -v mmdc >/dev/null && echo "✅ $(mmdc --version 2>/dev/null || echo '?')" || echo "⚠️ not installed — Mermaid blocks in .md will be skipped (SVGs still included); npm i -g @mermaid-js/mermaid-cli"`

## Approach

1. **Resolve feature + scan.** `--feature` required. Run the builder (it globs `.svg` + `.md` itself).
2. **L1 preview** — list how many diagrams, which tabs, which mermaid blocks will be included/skipped. Confirm.
3. **Build:**
   ```bash
   node "${CLAUDE_PLUGIN_ROOT:-.claude}/skills/gallery/resources/gallery-build.mjs" --feature {feature}
   ```
4. **Sanity-check the output** — confirm the file exists + the builder's summary line (N diagrams, M tabs). Open is the user's call.
5. **Activity log** — set `CLAUDE_SKILL_NAME=/gallery` + `CLAUDE_CHANGELOG_NOTE` ("built {feature} gallery") before/around the build.
6. **Output report.**

## Output report

```
✅ Gallery: docs/{feature}/{feature}-gallery.html
   {N} diagrams across {M} tabs: {tab list}
   {+ {K} mermaid blocks rendered | or: mermaid blocks skipped (install mmdc)}

Open the file in a browser (double-click). Switch tabs at the top; export the active tab via ⋯ (Copy/PNG/PDF).
Rebuild after adding diagrams: /gallery --feature {feature}.
```

## Gotchas

- **No diagrams yet** → the builder errors "No diagrams found"; draw some first (`/dfd`, `/system-design`, `/sequence`...), then rebuild.
- **Mermaid blocks skipped** — if `mmdc`/Chrome is missing, inline-Mermaid diagrams (sequence/state/erd/activity/mindmap/journey/timeline) are skipped while D2/PlantUML/BPMN `.svg`s are included. Install `@mermaid-js/mermaid-cli` + a Chrome to include Mermaid.
- **Self-inline risk** — the builder skips existing `*-gallery.html` / `*-system-design.html` / `*-architecture.html` so it never inlines a previous deck into itself.
- **Big decks** — many large SVGs → big HTML; that's expected for a handoff file.
- **Tab of "Other"** — diagrams in an unrecognized folder land here; rename/move the folder into a known type to get a labeled tab.
