# /bpmn — BPMN 2.0 Process Diagram (OMG standard, 2-layer architecture)

## Goal

Generate BPMN 2.0 for a multi-role business process, **draws correctly on run + business-accurate**.

**Shared ENGINE at `${CLAUDE_PLUGIN_ROOT:-.claude}/skills/bpmn/engine/`** (do NOT copy into each feature). Contains `bpmn-build.mjs` + `bpmn-layout-*.mjs` + `bpmn-semcheck.mjs` + `_viewer_template.html` + `node_modules` (installed once). Call it pointed at the feature via `--dir docs/{feature}/bpmn`.

**Per-feature OUTPUT** in `docs/{feature}/bpmn/` — ONLY 3-5 business files (no engine/deps):

1. `{process}.ir.json` — business **IR** generated by the AI. Source of intent. Edit this when calling the skill again to update.
2. `{process}.src.json` — source facts (actors/branches/errors) for coverage checks.
3. `{process}.bpmn` — full BPMN 2.0 XML (semantic + BPMNDiagram) generated by the engine. Import into Camunda/Bizagi/draw.io.
4. `{feature}-bpmn-editor.html` — drag-and-drop **editor** (bpmn-js modeler): edit like bpmn.io + Download/Save .bpmn buttons. Multi-process dropdown.
5. `{feature}-bpmn-index.md` — metadata + process table.

> **Do not duplicate the engine.** Previously the engine + node_modules were copied into each feature (18+ files/feature). Since 2026-07-09: the engine lives in one shared place, features keep only output.

## 2-layer architecture (CORE — do not change)

```
UC/SRS/flows ──(AI reads + infers)──► {slug}.ir.json   (lanes / nodes / flows)
                                       {slug}.src.json  (actors / branches / errors extracted from source)
                                          │
              bpmn-build.mjs:             ▼
   (A) semcheck ── structural MANDATORY pass (start/end, reachable, gateway ≥2 branches, no orphans)
                ── coverage: actor↔lane, branch↔gateway, error↔end  → warn if it diverges from source
                                          │ (ok)
   (B) layout engine ── no-lane: bpmn-auto-layout · vertical swimlane: grid (lane=column, step=row) — compute coordinates + routing
                                          ▼
                                  {slug}.bpmn  ──► {feature}-bpmn-editor.html
```

> **The AI ONLY generates the IR JSON + src facts. Do NOT write XML, do NOT compute coordinates.** The `bpmn-layout-auto.mjs` engine (bpmn-auto-layout) handles the entire layout. Semcheck `bpmn-semcheck.mjs` blocks business-invalid IR before drawing.
>
> **2 main engines, chosen by whether there are swimlanes:**
> - **No-lane (default)** = `bpmn-auto-layout` (official bpmn-io) — clean hand-drawn-like routing, OMG-standard `X` gateways, loop-backs that route around nicely. IR → pure BPMN semantic (NO coordinates) → `layoutProcess()` generates DI → auto-inserts `<BPMNLabel>`. **Lesson:** the library routes very well on its own; do NOT layer custom routing on top (clip/dogleg → "crooked" kinks). Hard limitation: **NO concept of swimlanes** (it only sets Lane size 400×100, does not partition nodes) — cannot be forced into lanes.
> - **VERTICAL swimlane (default when there are lanes)** = the custom-written grid engine `bpmn-layout-grid.mjs` (since 2026-07-13). **lane = COLUMN, step = ROW** (longest-path rank), nodes centered in the lane column, flow runs DOWNWARD. Fan-out gateway (each branch on a different edge — avoiding stacked bottom stubs), fan-in (multiple edges into 1 node attach at different top points), loops run along the right-edge corridor (not over the top). Enter via `BPMN_LANES=1` + IR with ≥2 lanes. Verify by inspecting vertical/horizontal overlap + task crossings → the grid engine PASSes clean.
> - `BPMN_ENGINE=grid` forces the vertical grid even for no-lane; `BPMN_ENGINE=elk` forces the old HORIZONTAL ELK swimlane (fallback, `bpmn-layout-elk.mjs`); `BPMN_ENGINE=legacy` the old 267-line custom engine.
>
> **Why a custom grid for swimlanes:** bpmn-auto-layout is pretty but does not do lanes (a hard bpmn-io limitation); ELK can partition but loops shoot over the top and cross + it does not compress same-lane nodes → ugly. The grid gives 100% control: nodes aligned by rank, clean vertical lanes (like hand-drawn draw.io), compact routing.
>
> **Lanes are OFF BY DEFAULT (no-lane / flat).** A flow with many lane-jumping branches → flat is still pretty & clear. Turn on swimlanes deliberately when the process has clear role separation (each role a contiguous cluster): `BPMN_LANES=1 node bpmn-build.mjs`. The IR still declares `lanes` (used for flowNodeRef + coverage).
>
> **Why IR?** It separates "understanding the business" (AI is good) from "drawing pixels" (the engine is good). AI getting coordinates wrong = disaster; AI generating business structure is trustworthy + checkable. IR also makes update mode edit only JSON, with layout regenerated automatically.

## Constraints

- **AI generates IR + src, does NOT generate XML.** Violating this = back to the same old problems (wrong coordinates, overlapping lines). The engine (auto-layout / grid) handles coordinates.
- **Lanes off by default.** Do NOT force swimlanes unless the user clearly wants them + the process has clean role separation. Most flows → no-lane looks better.
- **Structural semcheck must PASS** before there is a .bpmn. Coverage warning → review the business (missing actor/branch/error?), fix the IR if something is genuinely omitted.
- **L1 approval** before Write — BA-friendly prose (see `ba-conventions.md` Section 5), present the IR in business terms (roles / steps / branches), do NOT dump JSON.
- **NO L3 iterate** — review from `{feature}-bpmn-editor.html`.
- **Bilingual (mirror input — @../../rules/language.md)** in names; the engine escapes XML itself.
- **Per `diagram-selection.md`** — `/bpmn` when you need the OMG standard + BPM tool import / drag-and-drop editor. Multi-role ordinary business description (no engine needed) → `/activity-swimlane` (true swimlanes, lighter). Compact flow needing inline embedding → `/activity` (Mermaid).
- **1 process = 1 objective.** A process too large / 2 complex merged flows → split into 2 BPMNs (like email vs Google login), compact + a multi-process dropdown.
- **Idempotent** — `bpmn/{feature}-bpmn-index.md` tracks processes; matching slug → enter update mode automatically (L2 diff for the IR), no refusal.
- **`--feature` optional** — auto-detect from context/the feature in progress; only ask via picker when ambiguous. **Feature does not exist + arg is a process description → auto-derive slug + create feature** (entry point, see `feature-bootstrap.md` group A). Do NOT require going through `/brainstorm` first.

## Approach

1. **Resolve feature + process.** If only `<feature>` is given (no description) → read context, suggest which process to draw (many gateways/multi-role), ask the user to choose. Slug = verb-object kebab-case.
   - **Feature does not exist (entry point, per `feature-bootstrap.md` group A):** if the arg is a raw process description with no matching `docs/{feature}/` (e.g. `/bpmn "customer places an order, courier delivers, admin approves the refund"`) → `/bpmn` IS ALLOWED to bootstrap: derive the feature slug from the description (kebab-case, ASCII, ≤50 chars), confirm the slug at L1 (user can override), create `docs/{feature}/bpmn/` on Write. Do NOT require the user to run `/brainstorm` first.
2. **Read the business source** (if present, no fabrication): related UCs (`usecases/uc-*.md` Section b Actors, d Expected result + **Branches**, g Related FR), `srs/{feature}-flows.md`, `srs/{feature}-spec.md` Error Matrix.
   - **UC/SRS present** → extract facts from them (step 3), do not re-ask what already exists (no-re-ask).
   - **NO UC/SRS yet (new feature or old feature lacking a source)** → **interview EXACTLY the scope the BPMN needs** (per `feature-bootstrap.md` group A step 3), asking in one business-language batch (do NOT ask about DB/SDK): which **roles/lanes** participate · the main **steps** in order · **branch points** (decision question + branches) · **outcomes** (success + each error-path). Do NOT fabricate — ask about whatever is missing. This is a clarifying interview, just enough to draw correctly, not exhaustive like `/brainstorm`.
3. **Extract source facts** → `{slug}.src.json`:
   - `actors`: every actor in UC Section b (primary + supporting).
   - `branches`: every "If... then..." branch in UC Section d Branches.
   - `errors`: every related E-code (from UC + Error Matrix).
4. **Infer the IR** → `{slug}.ir.json`:
   - `lanes` = actors (one lane per actor; merge if same role).
   - `nodes`: 1 `start` (UC Section a/c trigger) · a `task` for each step (verb+object, lane = who does it) · a `gateway` for each branch point (from Branches) · an `end` for each outcome (success + each error-path).
   - `flows`: connect nodes per Expected result + Branches; each gateway-outgoing has `name` = the branch condition.
   - **The AI assigns each node's lane** (who is responsible for that step); columns/coordinates are NOT needed — the engine handles them.
5. **L1 plan preview** — BA-friendly prose:
   > I will create BPMN **{title}** in `docs/{feature}/bpmn/`:
   > - **{N} roles**: {list}
   > - **{M} steps** + **{K} branch points**: {1-line main branch}
   > - **{E} outcomes**: {list}
   > - Business coverage: {a actors / b branches / c errors} from UC {name}
   >
   > Apply? (Y / edit)
6. **Write** after user Y:
   - Create `docs/{feature}/bpmn/` (contains only OUTPUT — no longer copy the engine into the feature).
   - Write `{slug}.ir.json` + `{slug}.src.json`.
   - Run the SHARED engine pointed at the feature: `NODE_PATH="${CLAUDE_PLUGIN_DATA:-}/node_modules" node "${CLAUDE_PLUGIN_ROOT:-.claude}/skills/bpmn/engine/bpmn-build.mjs" --dir docs/{feature}/bpmn` → semcheck + layout → `{slug}.bpmn` + rebuild `{feature}-bpmn-editor.html` (in the feature dir).
   - Create/update `bpmn/{feature}-bpmn-index.md`.
7. **Call again with a matching slug** (automatic update mode) → L2 diff for `{slug}.ir.json`, then rerun `... bpmn-build.mjs --dir docs/{feature}/bpmn` (layout regenerates automatically).
8. **Verify** (MANDATORY): `NODE_PATH="${CLAUDE_PLUGIN_DATA:-}/node_modules" node "${CLAUDE_PLUGIN_ROOT:-.claude}/skills/bpmn/engine/bpmn-build.mjs" --dir docs/{feature}/bpmn --verify` → semcheck + clean layout. Structural error → fix the IR. Coverage warning → reconcile with the source. Do NOT report success while a ✗ remains.
9. **Activity log** — before Write set env `CLAUDE_SKILL_NAME=/bpmn` + `CLAUDE_CHANGELOG_AUTHOR={@author}` + `CLAUDE_CHANGELOG_NOTE=added BPMN {title} ({N} lanes, covers {a}/{b} branches)` (≤80 chars); the hook appends the whole line to `docs/_shared/activity.log`.
10. **Output report:**
    ```
    ✅ BPMN created: docs/{feature}/bpmn/{slug}.bpmn (OMG standard, swimlane)
       Roles: {N} | Steps: {M} | Branches: {K} | Outcomes: {E}
       Business coverage: actors {a}/{a} · branches {b}/{b} · errors {c}/{c}
       Verify: ✓ structural OK, clean layout

    View/edit: open docs/{feature}/bpmn/{feature}-bpmn-editor.html (drag-and-drop like bpmn.io)
    Import: drag {slug}.bpmn into Camunda/Bizagi/draw.io
    Edit:   call /bpmn "<change>" --feature {feature} again; I enter update mode automatically.
    ```

## IR schema (the AI generates exactly this format)

```jsonc
{
  "process": { "id": "Process_{slug}", "title": "Process name" },
  "lanes": [ { "id": "Lane_x", "name": "Role" } ],          // order = vertical band order
  "nodes": [
    { "id": "Start_1", "kind": "start",   "lane": "Lane_x", "name": "Trigger" },
    { "id": "Task_a",  "kind": "task",    "lane": "Lane_x", "name": "Verb + object" },
    { "id": "GW_a",    "kind": "gateway", "lane": "Lane_x", "name": "Decision question?" },
    { "id": "End_a",   "kind": "end",     "lane": "Lane_x", "name": "Outcome" }
  ],
  "flows": [
    { "id": "Flow_1", "src": "Start_1", "tgt": "Task_a" },
    { "id": "Flow_2", "src": "GW_a", "tgt": "Task_a", "name": "Branch label" }   // name MANDATORY for gateway branches
  ]
}
```

src.json: `{ "actors": [...], "branches": [...], "errors": [...] }` — facts extracted from the UC for semcheck to reconcile.

**IR rules** (enforced by semcheck): exactly 1 start · ≥1 end · gateway ≥2 outgoing with names · every node reachable from start + able to reach an end · no self-loops · unique ids. Loops (revise→draft) are valid — the engine detects the back-edge + routes around.

| File | Role |
|------|---------|
| `bpmn-semcheck.mjs` | Checks the IR: structural (blocks) + coverage (warns). Function `checkIR(ir, src)`. |

| `bpmn-build.mjs` | Pipeline: IR → semcheck → choose engine → .bpmn → viewer. `--verify` / `--no-ir`. |
| `_viewer_template.html` | bpmn-js CDN viewer, multi-process dropdown. |

## Gotchas

- **AI writing XML by hand = wrong purpose.** Only generate IR JSON. If the user pastes BPMN XML to edit → extract it back into IR, then re-layout.
- **Semcheck reports missing coverage** (e.g. "branch X has no gateway yet") → RE-READ the UC; if it is genuinely omitted add it to the IR; if that branch is out-of-scope it is OK to skip (a warning, not a block).
- **A process with 2 complex merged flows** (e.g. email+Google login together) → split into 2 BPMNs. The engine handles fan-out/fan-in well, but 1 process should have 1 objective.
- **Loop/back-edge** — the engine detects it (DFS) + routes around a top/bottom band. The AI just declares the return flow normally.
- **A gateway with 1 branch** — semcheck blocks it. A gateway must have ≥2 outgoing.
- **The viewer needs internet the first time** (bpmn-js CDN, like `/dashboard`). Strictly offline → at the user's request, inline the lib (~600KB).
- **Don't overuse** — linear single-role → `/sequence` / `/activity`; multi-role not needing the OMG standard/engine → `/activity-swimlane`.
